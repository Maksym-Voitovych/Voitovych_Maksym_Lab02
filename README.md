## Опис проєкту

Проєкт є продовженням системи управління банківськими рахунками з лабораторної роботи №1. Основна мета — використання структур даних Python, функціональної декомпозиції, генераторів, замикань і декораторів.

Проєкт організовано за допомогою `src-layout` і оформлено як Python-пакет.

## Використані концепції та структури даних

1. **Базові структури:** `list` для зберігання рахунків, `tuple` для типів рахунків, `set` для унікальних імен і `dict` для рахунків та індексації за номером.
2. **Модуль `collections`:** `defaultdict` для групування, `Counter` для статистики та `deque` для збереження історії останніх п'яти операцій.
3. **Функції та конструкції Python:**

   * Comprehensions для створення списків, множин і словників.
   * Генератори для обчислення загального капіталу та середнього балансу.
   * `*args` і `**kwargs` для роботи з аргументами функцій.
   * `lambda` для сортування та пошуку максимальних значень.
   * Замикання `create_min_balance_filter()` для фільтрації рахунків.
   * Декоратор `@log_execution(prefix="...")` для логування викликів і часу виконання функцій.

## Оцінка часової складності (Big-O)

| Операція         | Функція / метод            | Складність            |
| ---------------- | -------------------------- | --------------------- |
| Пошук за номером | `find_account()`           | \(O(1)\) у середньому |
| Фільтрація       | `filter_accounts()`        | \(O(n)\)              |
| Групування       | `group_accounts_by_type()` | \(O(n)\)              |
| Сортування       | `universal_sort()`         | \(O(n \log n)\)       |

Пошук використовує словниковий індекс, фільтрація перевіряє кожен рахунок, групування проходить усю колекцію, а сортування виконується вбудованою функцією `sorted()`.
